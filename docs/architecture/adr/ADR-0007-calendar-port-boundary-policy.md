# ADR-0007：CalendarPort、历法数据源与交节策略

状态：Accepted（2026-08-30 修订，辅助入口范围受限）

日期：2026-08-29

## Context

出生日期到四柱的换算受时区、节气交界、地点和真太阳时策略影响。系统以用户复核后的四柱为分析契约，并增加一个保守的公历录入辅助；它不能提升 `calendarVerified` 状态。

## Decision

- 领域层只依赖 `CalendarPort` 概念边界，不依赖具体历法库；
- 首个发布候选仅接受完整四柱，并执行干支周期一致性、时区已知和边界候选唯一性检查；
- 缺时柱、时区未知或交界存在多个候选时停止唯一结果发布；边界场景保留双候选，不猜测；
- 公历录入辅助锁定 `lunar-typescript@1.8.6`，只接受用户已换算成固定 `UTC+08:00` 的 1901—2099 年民用时间字段，不使用宿主 `Date` 时区换算；
- 辅助入口不处理出生地时区、历史夏令时、地点或真太阳时。交节前后 30 分钟、时辰边界前后 2 分钟及整个 23 时段停止自动填入；可计算时只填入现有手动四柱字段，用户仍须复核；
- 边界场景可显示交界两侧候选，但不会提交唯一选择；公历原始字段不进入当前 API 或档案；
- 合成测试可显式绕过历法一致性检查，但该标志不得由生产 API 接收。

## Consequences

- 当前 `calendarVerified=false` 是诚实的范围声明：辅助计算结果没有独立权威金样背书；
- 适配器记录引擎、精确版本、固定 UTC+8 口径及边界安全窗；依赖锁文件固定发布内容。调研与不可宣称能力见 `docs/research/calendar-adapter-research-2026-08-30.md`；
- 任何节奏或关系模块不得从当前结果推断具体公历时间。
