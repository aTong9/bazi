**版本：V0.1（架构基线）**

**内部名称：亲密互动与关系应对机制**  
**定位：五模型体系中的模型三设计底稿**  
**最终载体：Excel 总规则库；本文件用于先统一模型边界、术语、输入输出、模块职责、判断优先级和后续建设顺序。**

## 0. 使用原则

### 0.1 模型三描述“默认互动方式”，不评价好坏

模型三研究的是：

> **当关系已经建立，用户通常通过什么方式维持联结、表达在意、接受支持、协商边界、面对分歧，并重新恢复联系。**

它描述的是关系中的**行为惯性与处理顺序**，不是心理诊断，也不是婚姻结果判断。

用户语言统一采用：

- “你更习惯……”；
- “进入关系后，你往往先……”；
- “当分歧出现时，你可能更倾向……”；
- “在相对稳定的状态下，这种方式通常表现为……”；
- “压力增加时，表达顺序可能转为……”。

避免使用：

- “你就是冷漠／控制／回避／依赖”；
- “你一定会冷战／争吵／讨好”；
- “你的关系注定……”；
- “这种相处方式一定好／一定不好”。

### 0.2 单一事实源

模型三的正式规则最终只维护在：

> `M3_相处惯性总规则库.xlsx`

本设计文档负责解释架构；后续速查手册负责日常学习；程序所需 JSON 或数据库由 Excel 导出。不同文件不得分别维护互相独立的规则版本。

### 0.3 基础命理结果必须来自共享引擎

M3 不重新计算：

- 排盘；
- 十神映射；
- 月令与旺衰；
- 透藏与根气；
- 喜忌用神；
- 合、冲、刑、害、破；
- 真合化与假合；
- 五行流向是否成立。

这些信息必须由统一的“共享基础命理引擎”提供。模型三只负责把标准化命理事实翻译为**亲密互动方式**。

# 1. 五模型正式分工

| 模型 | 正式名称 | 核心问题 |
|---|---|---|
| M1 | 心动偏好 | 什么样的人最容易让我产生好感？ |
| M2 | 关系选择 | 什么样的人更容易被我接受并真正进入关系？ |
| M3 | 相处惯性 | 进入关系后，我通常怎样表达、依赖、付出、沟通与处理分歧？ |
| M4 | 关系盲点 | 哪些失衡模式、判断偏差和风险容易反复出现？ |
| M5 | 适配关系 | 什么样的伴侣特质、边界和互动结构更适合长期关系？ |

五个模型的顺序为：

```text
产生好感（M1）
        ↓
接受并进入关系（M2）
        ↓
实际怎样相处（M3）
        ↓
哪些惯性在失衡时容易形成问题（M4）
        ↓
怎样的关系结构更适合长期维持（M5）
```

模型三处于“进入关系”与“风险评估”之间，因此必须保持**中性、描述性和过程化**。

# 2. 模型定义与边界

## 2.1 正式名称

**模型三：相处惯性——进入关系后，你通常怎样靠近、表达、付出、沟通与处理分歧？**

可用于用户报告的副标题：

> **你的亲密互动方式、情绪处理顺序与关系修复路径**

## 2.2 核心任务

根据日柱关系底盘、夫妻宫十神结构、十神功能系统、日主承载与边界能力、有效五行流向及合冲刑害等状态修正，判断：

1. 用户进入关系后的基础互动角色；
2. 用户怎样表达喜欢、在意与关心；
3. 用户怎样投入时间、精力、资源和责任；
4. 用户怎样接受照顾、依赖他人或保留个人空间；
5. 用户怎样表达需求、处理情绪和沟通差异；
6. 用户在共同决策中偏向主导、协商、配合还是分工；
7. 分歧出现时，用户通常先做什么、后做什么；
8. 关系紧张后，用户通常通过什么方式恢复联结；
9. 用户在平稳状态与压力状态下是否存在明显行为切换；
10. 结论的证据来源、置信度及禁止延伸范围。

## 2.3 模型三允许回答的问题

模型三可以回答：

- 用户更习惯用语言、行动、陪伴、责任、照顾还是共同体验表达在意；
- 用户更需要高频回应、稳定陪伴、充分交流、现实落实，还是适度个人空间；
- 用户遇到情绪时更倾向即时表达、先整理后表达、先解决事情，还是先恢复安全感；
- 用户在关系中更习惯平等协商、主动推动、承担安排，还是根据情境切换；
- 用户发生分歧时更容易先澄清、先行动、先冷静、先确认事实，还是先确认彼此立场；
- 用户通常通过说清楚、做出改变、重新承诺、给予空间或共同经历完成修复；
- 用户的平时相处方式与压力状态下的反应是否一致；
- 为什么用户“明明在意，却不一定用对方容易识别的方式表达”；
- 为什么用户在不同关系阶段可能使用不同互动通道。

## 2.4 模型三不负责的问题

以下内容禁止混入 M3：

- 什么样的人最容易让用户心动——属于 M1；
- 什么样的人更容易被用户选进关系——属于 M2；
- 对方是否忠诚、成熟、善良或“是不是渣”——不由原局直接判断；
- 某种相处方式是否必然导致冷战、控制、出轨、分手或离婚——属于 M4 或结果模块；
- 用户是否存在依恋障碍、人格障碍、心理疾病——不得由八字判断；
- 谁付出更多、谁爱得更多——除非有明确现实材料，原局不做定量比较；
- 哪一种相处方式最适合用户——属于 M5；
- 何时争吵、何时复合、何时结婚——属于时运或事件模块；
- 性生活频率、具体性偏好或私密行为——不作为 M3 的固定推断。

## 2.5 模型边界检验句

每一条拟加入 M3 的规则，都必须通过以下检验：

> **这条结论是否只描述“关系建立后，用户通常如何互动与应对”？**

若结论开始回答：

- “这会造成什么伤害或风险”——转入 M4；
- “哪一种关系最适合”——转入 M5；
- “用户会不会选择这种人”——回到 M2；
- “用户为什么会心动”——回到 M1。

# 3. M2、M3、M4、M5 的严格区别

| 观察场景 | M2 关系选择 | M3 相处惯性 | M4 关系盲点 | M5 适配关系 |
|---|---|---|---|---|
| 核心问题 | 凭什么让一个人进入关系 | 进入后通常怎样互动 | 哪些惯性失衡后容易反复出问题 | 什么互动结构更容易长期适配 |
| 典型动词 | 接受、确认、选择、进入 | 表达、依赖、投入、沟通、修复 | 误判、过度、压抑、重复、失衡 | 匹配、互补、边界、节奏、支持 |
| 正官示例 | 需要看到守约和责任兑现 | 用承担、规则和稳定安排维持关系 | 可能把责任变成过度要求或僵化标准 | 适合怎样的责任边界与协商机制 |
| 七杀示例 | 需要看到行动、推进和承担 | 用解决问题、快速行动和保护表达在意 | 行动过快时可能压过沟通与感受 | 适合怎样的行动权和反馈机制 |
| 正印示例 | 被理解和安全感是进入门槛 | 通过倾听、安抚、承接与照顾维持联结 | 承接过度时可能形成代替决定或依赖 | 适合怎样的支持与自主平衡 |
| 伤官示例 | 需要充分交流后才能确认 | 习惯说清楚、分析、表达观点与提出问题 | 表达过强时可能变成批评或否定 | 适合怎样的沟通强度与反馈方式 |

一句话区分：

> **M2 是“我为什么愿意开始”；M3 是“开始以后我怎样相处”；M4 是“这种相处方式失衡后哪里容易出问题”；M5 是“怎样的互动结构更适合我”。**

# 4. 模型三的核心理论框架

M3 不以“夫妻星”作为唯一主轴，而以以下三层为核心：

```text
日柱与夫妻宫
决定关系中的基础运行环境
        ↓
五类十神功能系统
决定用户通过什么通道表达、投入、承接和协商
        ↓
流向、制化与合冲刑害
决定这些通道按照什么顺序启动、切换和恢复
```

## 4.1 日柱是“关系中的我与关系环境”

- 日干代表用户在亲密关系中的自我位置；
- 日支代表关系建立后的内部运行场域；
- 日支十神不直接等于配偶性格，而优先解释为：
  - 用户进入亲密关系后最容易进入什么互动主题；
  - 什么类型的关系体验会反复被关注；
  - 哪一种相处方式最靠近用户的关系核心。

## 4.2 五类十神功能系统

| 系统ID | 功能系统 | 包含十神 | 在 M3 中主要负责 |
|---|---|---|---|
| SYS01 | 自我边界系统 | 比肩、劫财 | 自主、平等、共同参与、边界与决定权 |
| SYS02 | 表达交流系统 | 食神、伤官 | 情绪表达、观点说明、轻松互动与需求沟通 |
| SYS03 | 投入经营系统 | 正财、偏财 | 时间、资源、日常安排、实际付出与共同体验 |
| SYS04 | 责任行动系统 | 正官、七杀 | 承诺、规则、承担、推进、保护与问题解决 |
| SYS05 | 承接内化系统 | 正印、偏印 | 接受支持、安全感、倾听、内在消化与个人空间 |

五个系统没有高低好坏。模型三只判断：

- 哪个系统最容易先启动；
- 哪个系统负责主要表达；
- 哪个系统负责接受与恢复；
- 哪些系统能够顺畅转换；
- 哪些系统在压力下会替代另一系统。

## 4.3 功能流转的基础循环

传统五行生助关系可在 M3 中转译为一条**潜在互动循环**：

```text
印：先获得理解、安全与内部确认
        ↓
比劫：形成自己的立场、边界和选择
        ↓
食伤：把感受、需求和观点表达出来
        ↓
财：把表达转成时间、行动和现实投入
        ↓
官杀：把投入转成责任、规则和共同承担
        ↓
印：责任兑现后重新形成安全与信任
```

该循环只提供潜在顺序，不能仅凭五行相生就断定现实中一定如此。至少需要日支、有效十神、位置或真实流向中的第二类证据支持。

# 5. 标准输入与输出契约

## 5.1 标准输入字段

### A. 基础信息

- 产品性别口径；
- 日主；
- 四柱干支；
- 十神位置映射；
- 日支及日支藏干；
- 当前只分析原局，还是原局加阶段信息；
- 共享旺衰、喜忌和合化结论及其置信度。

### B. 日柱与夫妻宫信息

- 日支主气、中气、余气对应十神；
- 日支主气是否稳定成立；
- 日支藏干主次是否清楚；
- 日干与日支之间的五行生克关系；
- 夫妻星是否进入日支；
- 日支是否受到合、冲、刑、害、破；
- 合化是否真正成立；
- 日支状态是否存在重大争议。

### C. 五系统有效性

每个系统至少提供：

- 是否形成有效信号；
- 正偏主次；
- 透干或藏支；
- 有根或无根；
- 强、中、弱；
- 喜、忌或未定；
- 与日干、日支的距离；
- 是否受到生、制、合、化；
- 是否存在可解释的流向；
- 是否在日柱附近形成直接互动证据。

### D. 自我承载与边界信息

- 日主有效状态；
- 印星对内部稳定和情绪消化的支持；
- 比劫对边界和自我表达的支持；
- 食伤是否有可用表达出口；
- 官杀、财星是否形成明显责任或投入压力；
- 日主与关系信号是否一方明显压倒另一方；
- 是否存在“知道但说不出”“能说但尚未想清楚”等分化结构。

### E. 互动流向信息

- 印→比劫是否成立；
- 比劫→食伤是否成立；
- 食伤→财是否成立；
- 财→官杀是否成立；
- 官杀→印是否成立；
- 是否存在制约筛选链；
- 是否存在直接流、桥接流、闭环流、断流或并行流；
- 同一条流向是否得到至少两个独立证据支持。

### F. 状态字段

- 透干／藏支／混合；
- 有根／无根／未定；
- 强／中／弱；
- 喜／忌／未定；
- 有制／无制／制化争议；
- 合而不化／真合化／未定；
- 近位／中位／远位；
- 单一／重复／正偏并见；
- 平稳状态／压力激活／恢复状态。

### G. M1、M2 接口

M3 可以读取但不能篡改：

- `M1.primary_attraction`
- `M1.primary_trigger`
- `M2.primary_gate`
- `M2.proof_needed`
- `M2.agency_pattern`
- `M2.confirmation_path`
- `M2.dual_structure`
- `M2.tempo`

接口用途：

- 比较“心动时看重什么”与“相处时怎样表达”；
- 比较“进入关系需要的证据”与“进入后实际使用的互动通道”；
- 识别从 M2 到 M3 的连续性或转换，但不把差异自动解释成问题。

## 5.2 标准输出字段

| 输出字段 | 含义 |
|---|---|
| `interaction_pattern` | 整体相处模式，只允许一个主模式 |
| `relationship_baseline` | 关系中最核心的运行主题 |
| `affection_expression` | 用户怎样表达喜欢和在意 |
| `care_investment` | 用户怎样投入时间、资源、行动与责任 |
| `support_receiving` | 用户怎样接受照顾、理解和支持 |
| `closeness_boundary` | 用户对靠近、独处、平等与边界的惯性 |
| `communication_style` | 用户怎样表达需求、情绪和观点 |
| `decision_pattern` | 共同事务中偏向主导、协商、分工或情境切换 |
| `conflict_response` | 分歧出现时最常见的第一反应与后续步骤 |
| `repair_path` | 紧张后怎样恢复联系与信任 |
| `stress_shift` | 压力状态下是否切换到另一互动通道 |
| `basis_summary` | 简明命理依据，供折叠展示 |
| `confidence` | 高／中高／中／中低／低／停止 |
| `boundary_note` | 提醒“相处惯性不等于关系风险或适配结论” |

最终用户正文不需要每次展示全部字段。简版报告建议保留：

1. 整体相处模式；
2. 表达与付出方式；
3. 亲密距离与沟通方式；
4. 分歧响应；
5. 修复路径；
6. 必要时说明压力切换。

# 6. 互动通道词典

所有命理信号先映射到统一的“互动通道”，再生成自然语言。

| 通道ID | 十神 | 通道名称 | 主要互动功能 | 用户可见关键词 |
|---|---|---|---|---|
| I01 | 比肩 | 平等并肩 | 同步参与、保留自我、平等协商 | 像队友、尊重边界、各自有主见 |
| I02 | 劫财 | 共同行动 | 快速参与、带动节奏、一起做事 | 有行动感、共同推进、边做边确认 |
| I03 | 食神 | 舒缓陪伴 | 温和表达、生活照顾、轻松联结 | 陪伴、体贴、幽默、相处舒服 |
| I04 | 伤官 | 表达澄清 | 说清感受、分析问题、观点交流 | 直接表达、有内容、需要讲明白 |
| I05 | 正财 | 稳定经营 | 持续投入、日常安排、实际照料 | 长期投入、生活落实、稳定行动 |
| I06 | 偏财 | 体验联结 | 灵活回应、共同体验、气氛与变化 | 有来有往、一起体验、保持活力 |
| I07 | 正官 | 责任维护 | 承诺、规则、角色责任、稳定秩序 | 有交代、守约、共同承担 |
| I08 | 七杀 | 行动解决 | 快速判断、推进、保护、解决问题 | 直接处理、关键时刻扛事、效率 |
| I09 | 正印 | 安全承接 | 倾听、安抚、照顾、稳定支持 | 理解、耐心、让人安心、被接住 |
| I10 | 偏印 | 深度内化 | 独立消化、洞察、私人空间、非标准支持 | 先想清楚、需要空间、重深度 |

### 6.1 通道不是固定人格标签

例如伤官通道成立，只能说明：

> 用户在亲密关系中更容易使用“表达、分析、澄清和观点交流”处理互动。

不能直接推出：

- 说话刻薄；
- 婚姻不顺；
- 一定伤官见官；
- 一定与伴侣争吵。

### 6.2 正偏十神必须分开

- 食神与伤官都属于表达系统，但前者偏舒缓、生活化，后者偏明确、观点化；
- 正财与偏财都属于投入系统，但前者偏持续经营，后者偏灵活回应与共同体验；
- 正官与七杀都属于责任行动系统，但前者偏规则、承诺和持续承担，后者偏决断、推进和问题解决；
- 正印与偏印都属于承接内化系统，但前者偏稳定安抚，后者偏独立消化与深度理解；
- 比肩与劫财都属于自我边界系统，但前者偏平等并肩，后者偏共同推动与即时参与。

# 7. 过程观察维度

互动通道回答“用户主要通过什么方式相处”，过程维度回答“这种方式怎样运行”。

| 维度ID | 过程维度 | 核心问题 |
|---|---|---|
| Q01 | 表达外显度 | 感受和需求是直接说出，还是先在内部处理？ |
| Q02 | 情绪处理顺序 | 先安抚、先分析、先行动，还是先确认立场？ |
| Q03 | 亲密距离节奏 | 更偏稳定靠近、弹性互动、并肩独立还是先退后进？ |
| Q04 | 投入连续性 | 付出是持续稳定、事件驱动、灵活回应还是阶段性集中？ |
| Q05 | 决策分配方式 | 更偏主导、协商、明确分工、跟随事实还是情境切换？ |
| Q06 | 分歧启动方式 | 先说清楚、先解决、先冷静、先确认事实还是先维持秩序？ |
| Q07 | 修复启动方式 | 通过语言、行动、承诺、照顾、共同体验还是空间后重连？ |
| Q08 | 状态切换程度 | 平稳状态与压力状态下是否使用不同互动通道？ |

M3 最终必须是：

> **一个主互动通道＋若干过程维度修正**

而不是把十个十神标签全部拼成一段万能描述。

# 8. 知识层级

## L0：共享基础命理特征

由底层引擎提供十神、旺衰、透藏、根气、喜忌、合化、位置和流向。

## L1：关系运行底盘

最高优先级证据：

- 日支主气十神；
- 日支主气是否有效；
- 日支主、中、余气的主次关系；
- 日干与日支的生克关系；
- 日支是否被真合化；
- 日支是否存在严重争议。

L1 主要决定：

- `relationship_baseline`
- `interaction_pattern`

## L2：主要互动通道

从五个十神功能系统中识别：

- 主通道；
- 次通道；
- 正偏分工；
- 直接通道或隐性通道。

L2 主要决定：

- `affection_expression`
- `care_investment`
- `support_receiving`
- `communication_style`

## L3：亲密距离与边界

重点读取：

- 比肩、劫财；
- 正印、偏印；
- 官杀与日主相对状态；
- 日支比劫、印星或官杀结构；
- M2 的 `agency_pattern` 作为参考接口。

L3 主要决定：

- `closeness_boundary`
- `decision_pattern`

## L4：分歧响应

重点读取：

- 食伤表达出口；
- 官杀行动和规则系统；
- 印星内化与恢复系统；
- 比劫立场和边界系统；
- 日支合冲刑害破；
- 制约链与断流状态。

L4 主要决定：

- `conflict_response`

## L5：修复与重新联结

重点读取：

- 哪条互动流向能够从紧张状态回到关系底盘；
- 是否有语言、行动、承诺、照顾或空间中的可用恢复通道；
- 是否存在闭环或桥接；
- 是否只能得到低置信候选。

L5 主要决定：

- `repair_path`

## L6：状态切换

区分：

- 平稳基线；
- 轻度压力激活；
- 高压状态；
- 恢复状态。

L6 只描述行为顺序变化，不输出风险结论。

## L7：M1—M2—M3 接口

比较：

- 心动特质；
- 进入条件；
- 相处方式；

三者是连续、部分转换，还是明显不同。

## L8：总合成与边界审查

负责：

- 同源去重；
- 主次裁决；
- 置信度；
- 停止条件；
- 用户报告生成；
- 禁止推断审查。

# 9. 日支十神的基础关系底盘

日支十神是 M3 的最高优先级证据之一，但只解释关系环境和互动主题，不直接等于配偶性格。

| 日支主气十神 | 基础关系底盘 | 进入关系后更容易关注 | 用户解释方向 |
|---|---|---|---|
| 比肩 | 平等并肩 | 自主、尊重、共同参与 | 你更习惯把伴侣当作可以平等商量、各自保留自我的队友。 |
| 劫财 | 共同行动 | 参与感、节奏、一起推进 | 关系里有共同目标、一起做事和即时回应时，你更容易感到联结。 |
| 食神 | 舒缓陪伴 | 舒适、生活感、温和互动 | 你更习惯用陪伴、照顾日常和轻松交流维持亲密感。 |
| 伤官 | 表达澄清 | 交流、理解、观点和反馈 | 关系里能不能把话说清楚、彼此回应观点，对你十分重要。 |
| 正财 | 稳定经营 | 日常投入、安排、持续性 | 你更容易通过长期投入、现实安排和稳定行动经营关系。 |
| 偏财 | 体验联结 | 互动感、新鲜体验、灵活回应 | 你会通过有来有往的互动和共同体验维持关系活力。 |
| 正官 | 责任维护 | 规则、承诺、角色和秩序 | 你更习惯通过守约、承担和稳定安排维持关系。 |
| 七杀 | 行动解决 | 决策、推进、保护和效率 | 遇到事情时，你更容易通过迅速处理和承担行动表达在意。 |
| 正印 | 安全承接 | 理解、照顾、稳定回应 | 你重视关系中能否被理解和接住，也常通过倾听和照顾维持联结。 |
| 偏印 | 深度内化 | 私人空间、洞察、独立处理 | 你往往需要先在内部想清楚，再以较有深度或非直接的方式回应关系。 |

## 9.1 日支藏干主次

- 主气：优先描述日常关系底盘；
- 中气：常作为第二互动通道，可能在深入相处或特定情境中明显；
- 余气：只作为潜在补充，除非有透干、有根或其他独立证据加强；
- 多个藏干不能直接全部列为“核心相处模式”；
- 主气受损、真合化或状态争议时，必须降低主气权重。

## 9.2 夫妻星进入日支

夫妻星入日支时：

- 可以增强“伴侣资格标准”与“相处方式”之间的连续性；
- 不能因此把 M2 的资格证据重复算作 M3 的独立证据；
- 需要区分：
  - M2：对方怎样证明自己；
  - M3：用户进入关系后怎样回应和维持。

## 9.3 日支被合、冲、刑、害、破

在 M3 中仅作为互动节奏修正：

| 关系 | M3 中可用的中性含义 | 禁止直接推出 |
|---|---|---|
| 合 | 倾向协调、绑定、兼顾或把关系纳入整体安排 | 一定恩爱、一定黏人 |
| 冲 | 差异更容易外显，互动节奏可能变化或需要直接调整 | 分手、离婚、婚姻不稳 |
| 刑 | 容易反复校正、内部纠结或对细节较敏感 | 必然争吵、互相伤害 |
| 害 | 某些感受可能不立即说清，需要更多确认和间接处理 | 背叛、第三者、欺骗 |
| 破 | 原有节奏或约定可能需要重新调整 | 关系破裂 |
| 真合化 | 原有底盘需要根据化神重新解释 | 仍按原十神机械输出 |

# 10. 十神在模型三中的基础职责

## 10.1 比肩：平等并肩

内部功能：

- 保留自我；
- 强调平等；
- 共同参与；
- 各自承担；
- 以伙伴身份进入关系。

标准用户语言：

> 你更习惯把关系建立在平等和尊重之上。即使亲密，你也希望双方都保留自己的判断和空间，重要事情能够像队友一样商量。

禁止直接推出：

- 自私；
- 不愿付出；
- 不需要伴侣；
- 一定强势。

## 10.2 劫财：共同行动

内部功能：

- 快速参与；
- 带动气氛；
- 一起行动；
- 在共同任务中建立联结；
- 对关系节奏反应较快。

标准用户语言：

> 你更容易在“一起做事、一起推进、一起经历”的过程中感到亲近。相比长时间停留在口头确认，实际参与感往往更能让你进入关系状态。

禁止直接推出：

- 争抢；
- 第三者；
- 花钱冲动；
- 一定与伴侣竞争。

## 10.3 食神：舒缓陪伴

内部功能：

- 温和表达；
- 日常照顾；
- 放松气氛；
- 通过饮食、生活和陪伴传递在意；
- 倾向减少过度紧张。

标准用户语言：

> 你常通过陪伴、照顾日常和让相处更轻松来表达在意。对你来说，关系里的舒适感和生活感，本身就是一种重要的爱意表达。

禁止直接推出：

- 没有原则；
- 一味迁就；
- 只重享受；
- 不处理问题。

## 10.4 伤官：表达澄清

内部功能：

- 说出观点；
- 分析问题；
- 澄清误会；
- 需要回应和理解；
- 通过语言建立真实感。

标准用户语言：

> 你更习惯把感受和问题说清楚。关系里如果缺少真实交流，你很难只靠默认和猜测维持亲密；对方能否回应你的观点，对你很重要。

禁止直接推出：

- 说话伤人；
- 伤官见官必吵；
- 不尊重伴侣；
- 婚姻不顺。

## 10.5 正财：稳定经营

内部功能：

- 持续投入；
- 日常安排；
- 现实落实；
- 稳定资源分配；
- 通过可重复行动维持关系。

标准用户语言：

> 你表达在意时更重视持续和落实。安排时间、照顾生活、承担日常事务，往往比一时热烈更能代表你的认真。

禁止直接推出：

- 只在乎钱；
- 计较；
- 男命才适用；
- 一定传统顾家。

## 10.6 偏财：体验联结

内部功能：

- 灵活回应；
- 创造共同体验；
- 维持互动活力；
- 通过社交、活动、惊喜或变化表达在意；
- 根据情境快速调整。

标准用户语言：

> 你常通过共同体验和有来有往的互动保持亲密感。关系里有新鲜内容、轻松回应和一定流动性时，你更容易保持投入。

禁止直接推出：

- 花心；
- 不稳定；
- 只追求刺激；
- 一定有多段关系。

## 10.7 正官：责任维护

内部功能：

- 守约；
- 承担角色；
- 维持秩序；
- 对共同事务有交代；
- 用稳定规则保护关系。

标准用户语言：

> 你往往通过守约、承担和稳定安排表达认真。关系进入确定状态后，你会更关注双方是否把责任说清楚，并持续做到。

禁止直接推出：

- 控制欲；
- 古板；
- 只讲规则不讲感情；
- 配偶一定有身份。

## 10.8 七杀：行动解决

内部功能：

- 快速决策；
- 推进事情；
- 处理危机；
- 保护和承担；
- 通过解决问题表达在意。

标准用户语言：

> 遇到问题时，你更容易直接进入处理和解决状态。比起反复描述情绪，你可能先把事情推进、把困难处理掉，再回头谈感受。

禁止直接推出：

- 暴躁；
- 暴力；
- 控制伴侣；
- 一定压过对方。

## 10.9 正印：安全承接

内部功能：

- 倾听；
- 安抚；
- 稳定回应；
- 接受和给予照顾；
- 通过理解恢复关系安全。

标准用户语言：

> 你重视关系里能不能彼此理解和接住。你可能通过倾听、耐心回应和照顾情绪表达在意，也需要在被理解后更容易放松下来。

禁止直接推出：

- 依赖；
- 妈宝；
- 没有行动力；
- 一定喜欢被照顾。

## 10.10 偏印：深度内化

内部功能：

- 先独立消化；
- 从深层理解问题；
- 需要私人空间；
- 使用非标准、间接或专业化的支持方式；
- 经过思考后再回应。

标准用户语言：

> 你遇到复杂感受时，往往需要先留一点空间，把事情在内部想清楚。你的关心未必总是高频外显，但可能体现在理解细节、提供独特视角或在关键处回应。

禁止直接推出：

- 冷漠；
- 回避型依恋；
- 不会表达爱；
- 与伴侣疏离。

# 11. 初始相处模式

M3 V0.1 先建立 12 类相处模式，后续由真实案例校准主次与命名。

| 模式ID | 模式名称 | 核心通道 | 一句话定义 |
|---|---|---|---|
| P01 | 平等伙伴型 | 比肩 | 通过平等协商、各自承担和尊重空间维持关系 |
| P02 | 共同行动型 | 劫财 | 通过一起做事、一起推进和即时参与建立联结 |
| P03 | 舒缓陪伴型 | 食神 | 通过温和互动、生活照顾和轻松氛围表达爱意 |
| P04 | 表达澄清型 | 伤官 | 通过说清感受、交换观点和及时反馈维持真实感 |
| P05 | 稳定经营型 | 正财 | 通过持续投入、日常安排和现实落实维持关系 |
| P06 | 体验联结型 | 偏财 | 通过共同体验、灵活回应和互动活力维持亲密 |
| P07 | 责任维护型 | 正官 | 通过守约、规则和共同承担维持关系秩序 |
| P08 | 行动解决型 | 七杀 | 通过决断、推进、保护和解决问题表达在意 |
| P09 | 安全承接型 | 正印 | 通过理解、倾听、照顾和稳定回应维持联结 |
| P10 | 深度内化型 | 偏印 | 通过独立消化、深度理解和空间后回应处理关系 |
| P11 | 双通道协同型 | 两项独立主通道 | 两种互动方式有明确分工并能相互转换 |
| P12 | 情境切换型 | 多信号主次不定 | 不同场景稳定触发不同相处方式，无法用单一路径概括 |

### 11.1 主模式成立条件

至少满足：

1. 关系底盘或日柱附近存在对应信号；
2. 对应十神系统有效；
3. 不是仅凭一处无根、弱远或争议信号；
4. 没有被真合化后仍机械保留原性质；
5. 至少有一项独立修正证据支持其进入最终输出。

### 11.2 双通道成立条件

不能因为两项十神都旺就直接输出 P11。必须确认：

- 两项解决不同互动任务；
- 两项来自独立证据；
- 同源重复已经去重；
- 能说明先后、并行或场景分工；
- 两项都达到最低置信阈值。

# 12. 八个核心判断领域

## 12.1 情感表达：我怎样让对方知道我在意

优先证据：

1. 食神、伤官；
2. 日支主气；
3. 财、官杀、印中的辅助表达；
4. 透藏与位置；
5. 有效流向。

基础类型：

| 类型 | 主要证据 | 表达方式 |
|---|---|---|
| 温和陪伴型 | 食神 | 陪伴、照顾日常、营造舒适感 |
| 语言澄清型 | 伤官 | 说出感受、解释观点、及时反馈 |
| 实际行动型 | 财、官杀 | 安排时间、解决问题、承担责任 |
| 理解承接型 | 印 | 倾听、安抚、提供理解与支持 |
| 共同参与型 | 比劫 | 一起做事、共同决策、并肩承担 |
| 隐性表达型 | 藏支、偏印或无明显外显出口 | 通过细节、关键回应或事后行动表达 |

注意：

> “表达少”不等于“感情少”；“行动多”也不等于“完全不需要语言”。

## 12.2 付出与经营：我怎样投入关系

优先证据：

1. 正财、偏财；
2. 正官、七杀；
3. 食神、正印；
4. 日支与流向。

基础类型：

- 正财：持续、稳定、日常化投入；
- 偏财：灵活、即时、体验型投入；
- 正官：承担职责和约定；
- 七杀：解决困难和推进事务；
- 食神：生活照顾和舒适支持；
- 正印：情绪承接和耐心陪伴。

M3 只描述付出渠道，不比较谁付出更多，也不判断对方是否珍惜。

## 12.3 接受支持：我怎样被照顾、怎样产生依赖感

优先证据：

1. 正印、偏印；
2. 日支印星、比劫或官杀；
3. 日主有效状态；
4. M2 的选择自主度仅作背景；
5. 流向是否能从外部行动回到内部安全。

基础类型：

- 正印：通过稳定理解、耐心回应和熟悉感接受支持；
- 偏印：通过深度理解、尊重空间和非标准回应接受支持；
- 比劫：在不失去自主的前提下接受支持；
- 官杀：更容易通过对方承担、处理事情和守住承诺感到被支持；
- 财：更容易通过持续现实行动确认支持存在。

禁止把印旺直接解释为“依赖型”，也不能把比劫旺直接解释为“不需要支持”。

## 12.4 亲密距离与边界

优先证据：

1. 比肩、劫财；
2. 正印、偏印；
3. 官杀对关系角色的约束；
4. 日主承载；
5. 日支主题和位置。

初始类型：

| 类型 | 说明 |
|---|---|
| 稳定靠近型 | 通过稳定回应和持续陪伴维持亲密 |
| 平等并肩型 | 亲密与自主同时存在，重视尊重和协商 |
| 弹性互动型 | 联系强度随场景调整，但需要保持回应感 |
| 空间后重连型 | 复杂情绪时先独立整理，再重新靠近 |
| 共同任务型 | 在共同目标和实际协作中感到亲近 |
| 状态不定型 | 多信号冲突或证据不足，暂不固定 |

## 12.5 沟通与情绪处理

优先证据：

1. 食伤表达；
2. 印星内化；
3. 官杀行动和秩序；
4. 比劫立场；
5. 透藏与流向。

初始沟通路径：

```text
路径 C01：先感受安全 → 再形成立场 → 再表达
路径 C02：先表达问题 → 再落实行动
路径 C03：先解决事情 → 再回到感受
路径 C04：先独立整理 → 再选择性沟通
路径 C05：先确认彼此立场 → 再共同协商
路径 C06：先观察事实和投入 → 再表达判断
路径 C07：语言与行动并行
路径 C08：情境切换／低置信
```

## 12.6 共同决策与角色分配

优先证据：

1. 比劫与官杀；
2. 日主和关系力量的相对状态；
3. 日支；
4. 财星的现实执行；
5. M2 SELF 接口。

初始类型：

- 平等协商；
- 一方主动推动、双方反馈；
- 角色清楚、分工明确；
- 依据事实和现实条件调整；
- 情境切换；
- 暂不判断。

禁止使用“谁压谁”“谁管谁”作为无条件输出。

## 12.7 分歧响应

M3 只回答：

> **分歧出现时，用户通常先使用哪一种处理通道。**

初始类型：

| ID | 类型 | 常见第一步 |
|---|---|---|
| CF01 | 直接澄清型 | 先把问题和观点说清楚 |
| CF02 | 行动解决型 | 先处理现实问题或迅速推进 |
| CF03 | 安全恢复型 | 先降低情绪强度、确认关系仍安全 |
| CF04 | 内部整理型 | 先独处、思考、形成清楚结论 |
| CF05 | 责任秩序型 | 先确认规则、承诺和责任边界 |
| CF06 | 事实投入型 | 先看实际行动和持续表现 |
| CF07 | 平等协商型 | 先确认双方立场和决定权 |
| CF08 | 双阶段／情境型 | 根据分歧类型切换两种以上步骤 |

禁止把任何类型直接翻译成“冷战、暴怒、逃避、讨好、控制”。这些属于 M4 在失衡条件下的进一步评估。

## 12.8 修复与重新联结

修复路径回答：

> **当关系紧张后，什么行为最容易让用户重新进入可沟通、可合作或可亲近的状态。**

初始类型：

| ID | 修复方式 | 主要通道 |
|---|---|---|
| RP01 | 语言复盘 | 食伤：把误会和感受重新说清楚 |
| RP02 | 实际改变 | 财：用持续行动证明调整 |
| RP03 | 承诺重建 | 官：明确规则、责任和后续安排 |
| RP04 | 问题处理 | 杀：把现实困难处理掉、降低压力 |
| RP05 | 情绪承接 | 正印：倾听、安抚、确认关系安全 |
| RP06 | 空间后重连 | 偏印：先整理，再选择合适方式回应 |
| RP07 | 共同经历 | 比劫／偏财：通过一起做事或共同体验恢复联结 |
| RP08 | 多通道／未定 | 两种路径并行、先后或证据不足 |

修复方式不等于“谁先道歉”，也不能推出关系一定能够修复成功。

# 13. 平稳、压力与恢复三种状态

M3 必须把同一个十神的“平稳表达”与“压力激活”分开。

## 13.1 平稳基线

当信号有效、承载良好、制化有序时，优先使用成熟表达：

- 食神：温和陪伴；
- 伤官：清楚表达；
- 正财：持续经营；
- 偏财：灵活互动；
- 正官：责任维护；
- 七杀：行动解决；
- 正印：稳定承接；
- 偏印：深度消化；
- 比肩：平等并肩；
- 劫财：共同推动。

## 13.2 压力激活

当信号过旺、受堵、无出口或外部结构明显触发时，M3 只描述**通道变化**：

- 表达通道可能从温和转为更直接；
- 行动通道可能先于情绪沟通启动；
- 印星通道可能需要更长内部整理；
- 比劫通道可能先强调立场和空间；
- 官杀通道可能先确认规则、责任或事实。

不能在 M3 中直接贴上“过度、伤害、问题人格”等标签。

## 13.3 恢复状态

恢复状态必须寻找真正可用的回流通道：

- 语言能否转成行动；
- 行动能否形成责任兑现；
- 责任兑现能否恢复安全；
- 安全是否支持重新表达；
- 是否需要空间后再进入沟通；
- 是否有闭环或桥接证据。

如果没有可用恢复通道，只能输出：

> “目前能够识别分歧时的第一反应，但修复路径证据不足。”

不能因此断言关系无法修复。

# 14. 信号状态的统一语义

## 14.1 透干与藏支

- 透干：互动方式更容易被对方直接看见，也更容易被用户主动使用；
- 藏支：互动方式较私密、间接或需要熟悉后才出现；
- 透干不等于稳定；藏支不等于不会表达。

## 14.2 有根与无根

- 有根：该互动方式更有持续性，较可能在多个场景重复出现；
- 无根：可能是阶段性、情境性或表达意愿大于实际稳定度；
- 无根不等于完全无效，需要结合位置和其他支持。

## 14.3 旺与弱

- 旺：该通道更容易被启动或反复使用；
- 弱：不一定没有，只是不宜作为唯一主模式；
- 旺不等于成熟，弱不等于缺陷。

## 14.4 喜忌

在 M3 中：

- 喜且平衡：该通道更容易以稳定、可协调的方式出现；
- 忌或失衡：同一通道可能更强烈、更僵硬或更容易在压力下先行；
- 喜忌未定：只描述通道内容，不判断成熟度。

喜神不等于“用户喜欢这样相处”；忌神也不等于“用户讨厌这样相处”。

## 14.5 近位与远位

- 近位：更容易直接进入亲密关系互动；
- 远位：可能更多在外部生活、工作或社会角色中体现；
- 远位若无其他关系证据，只能作为背景修正。

## 14.6 制、合与化

- 有制：原始通道受到调节，表达更有边界或顺序；
- 无制：不能直接判断失控，只表示原始功能较直接；
- 合而不化：两种互动功能可能同时牵引，需要判断分工；
- 真合化：原信号不再机械保留，按化神和新系统重新解释；
- 制化争议：降低置信度，不强行合成。

## 14.7 合冲刑害破

这些关系仅修正互动节奏，不直接判断关系吉凶：

- 合：协调、兼顾、绑定或纳入共同安排；
- 冲：差异外显、节奏变化、需要调整；
- 刑：重复校正、内在拉扯、对细节敏感；
- 害：感受不完全直接表达，需要额外确认；
- 破：既有节奏或约定需要改写。

# 15. 字段权威与判断优先级

模型三不使用一套总分覆盖所有问题，而采用“字段主权威”。

| 最终字段 | 第一权威 | 第二权威 | 主要修正 |
|---|---|---|---|
| `interaction_pattern` | 日支主气与日柱底盘 | 有效主系统 | 状态、流向、藏干主次 |
| `relationship_baseline` | 日支 | 日干—日支关系 | 合冲刑害与真合化 |
| `affection_expression` | 食伤系统 | 日支与财／印／官辅助 | 透藏、位置、出口 |
| `care_investment` | 财系统 | 官杀、食神、正印 | 根气、连续性、流向 |
| `support_receiving` | 印系统 | 日支、比劫与日主承载 | 远近、空间需求 |
| `closeness_boundary` | 比劫＋印 | 日主承载、官杀 | 日支与 M2 SELF 接口 |
| `communication_style` | 食伤＋印 | 官杀、比劫 | 透藏、制化、流向 |
| `decision_pattern` | 比劫＋官杀 | 财与日主相对状态 | M2 agency 仅作背景 |
| `conflict_response` | 日支动态＋可用主通道 | 食伤、官杀、印、比劫 | 制约链、压力状态 |
| `repair_path` | 有效回流路径 | 日支与可用支持通道 | 闭环、桥接、断流 |
| `stress_shift` | 强弱失衡与制化 | 合冲刑害、备用通道 | 只做条件性输出 |

## 15.1 总体判断顺序

```text
第一步：确认共享基础命理字段可用
第二步：确定日支主气及关系底盘
第三步：识别五系统主次和正偏分工
第四步：分别判断表达、投入、承接、边界
第五步：建立沟通和情绪处理顺序
第六步：判断分歧第一反应
第七步：寻找真实可用的修复回路
第八步：区分平稳与压力状态
第九步：处理双通道、同源去重和冲突
第十步：生成用户语言并做边界审查
```

## 15.2 证据优先级

建议从高到低：

1. 日支主气有效且状态清楚；
2. 日柱附近透干有根的十神系统；
3. 至少两项独立证据形成明确流向；
4. 主气＋中气的分工结构；
5. 远位、余气、单一无根信号；
6. 仅凭合冲刑害的孤立推断。

## 15.3 输出数量限制

最终报告最多保留：

- 1 个主相处模式；
- 1 个次级互动通道；
- 1 个主要表达方式；
- 1 个主要边界／距离模式；
- 1 个分歧响应；
- 1 个修复路径；
- 必要时 1 个压力切换说明。

不能把所有可用十神全部堆进用户正文。

# 16. 初始评分与合成框架

以下分值只用于知识库工程中的候选排序，不是统计概率，也不是命理准确率。

## 16.1 主模式候选分值

| 证据 | 初始作用 |
|---|---:|
| 日支主气有效 | +35 |
| 日支中气有效且有独立支持 | +15 |
| 日支余气有效且透／有根 | +8 |
| 日柱近位透干有根 | +20 |
| 同系统两项独立证据 | +12 |
| 清晰生助或回流路径 | +10 |
| 喜且平衡／制化有序 | +6 |
| 仅远位或无根 | 降权，不单独成主结论 |
| 真合化改变性质 | 原信号停止或改道 |
| 基础状态争议 | 降低置信度或停止 |

## 16.2 同源去重

同一个命理事实可能同时被多个模块读取，例如：

```text
日支正印
→ 关系底盘：安全承接
→ 支持接收：需要理解和稳定回应
→ 冲突响应：先恢复安全
```

这三项可以分别解释，但只能算作一个基础 `source_id`，不能当成三条独立证据反复加分。

## 16.3 双通道触发建议

两项通道同时进入用户输出，至少满足：

- 两项分别达到最低阈值；
- 两项功能不同；
- 有明确先后、并行或场景分工；
- 同源去重后仍有独立证据；
- 分差不足以确立单一主导。

否则应输出：

> 主通道＋次级修正

而不是“双核心”。

# 17. M1—M2—M3 接口

## 17.1 心动、选择、相处高度连续

示例：

```text
M1：欣赏可靠、负责的人
M2：需要持续守约和责任兑现才进入关系
M3：进入后也通过承担、安排和守约维持联结
```

用户语言：

> 你的心动标准、进入条件和相处方式较为一致。你不仅会被责任感吸引，也会用持续承担和明确安排经营关系。

## 17.2 心动与相处方式不同

示例：

```text
M1：容易被有趣、会表达的人吸引
M2：现实中需要稳定投入才会确认关系
M3：进入后自己更习惯用行动和安排表达在意
```

用户语言：

> 让你产生感觉的可能是交流和趣味，但真正进入关系后，你更常用稳定行动和现实投入维持联结。心动入口和日常经营并不是同一种语言。

不能把这种差异解释成虚伪、矛盾或不爱。

## 17.3 选择自主度与相处主导权不同

M2 的 `agency_pattern` 只表示进入关系时怎样做决定，不等于进入关系后谁主导所有互动。

例如：

- M2 主动筛选，不自动等于 M3 主导关系；
- M2 易受对方节奏推动，不自动等于 M3 没有边界；
- M3 的共同决策必须重新读取比劫、官杀、日主和日支。

## 17.4 接口证据不足

任何一个模型停止或置信度过低时，不做跨模型比较。

# 18. 自然语言合成规范

## 18.1 简版用户输出结构

### 第一段：整体相处模式

> 进入关系后，你更习惯以________的方式维持联结。对你来说，关系能够稳定运行，通常需要________。

### 第二段：表达与付出

> 你表达在意时，最常使用的是________。相比________，你更容易通过________让对方感受到你的认真。

### 第三段：亲密距离与沟通

> 在亲密和个人空间之间，你更偏向________。遇到复杂感受时，你通常先________，再________。

### 第四段：分歧响应

> 出现分歧时，你的第一反应往往是________。这不一定代表你不在意，而是你更习惯先通过________恢复可处理状态。

### 第五段：修复路径

> 真正让你重新进入联结状态的，通常是________。当对方／双方能够________时，你更容易重新开放沟通。

### 第六段：压力切换（有证据才输出）

> 平时你更偏向________；压力增加时，可能暂时切换为________。这描述的是处理顺序变化，不等于关系一定出现问题。

## 18.2 推荐用词

优先使用：

- 表达；
- 承接；
- 投入；
- 协商；
- 整理；
- 推进；
- 回应；
- 维持；
- 恢复；
- 重新联结；
- 需要空间；
- 先……再……；
- 在……情况下更明显。

谨慎或禁止使用：

- 冷漠；
- 恋爱脑；
- 控制欲；
- 讨好型；
- 回避型；
- 焦虑型；
- 情绪不稳定；
- 不会爱人；
- 自私；
- 强势；
- 注定冷战。

这些词只有在后续 M4 经过明确失衡规则和现实验证后，才可能用更中性的方式讨论。

| `version` | 版本号 |

### 20.1 M3 特有的证据记录

每条规则还应在 `notes` 或后续扩展字段中记录：

- `interaction_state`：平稳／压力／恢复；

- `recovery_channel`：修复通道；
- `cross_model_ref`：M1 或 M2 接口来源。

如果开发需要，后续可在不破坏 31 字段主表的前提下扩展为 JSON 子对象。

# 23. 案例验证框架

## 23.1 不能只问“你觉得像不像”

案例验证必须询问现实行为：

### 表达与付出

- 你通常怎样让伴侣知道你在意？
- 你更常用语言、行动、陪伴、礼物、安排、责任还是倾听？
- 伴侣最常抱怨“看不懂你哪一点”？

### 支持与距离

- 难过时你希望对方怎么回应？
- 你更需要立即陪伴，还是先留空间？
- 亲密关系中，你怎样判断自己的边界被尊重？

### 沟通与分歧

- 发生误会时，你通常第一步做什么？
- 你会立即谈、先冷静、先解决事情，还是先观察对方行动？
- 你在冲突中最难做到的是哪一步？

### 修复

- 什么行为最能让你愿意重新沟通？
- 你更看重道歉、解释、实际改变、承诺，还是给空间？
- 过去几段关系中，修复方式是否重复出现？

### 状态差异

- 平时和压力大时，你的相处方式是否明显不同？
- 哪些情境会让你从“愿意说”变成“先处理事情”或“先独处”？

## 23.2 案例字段

| 字段 | 内容 |
|---|---|
| 案例ID | 唯一编号 |
| 基础命盘事实 | 只记录共享引擎已确认字段 |
| 模型预期 | 各输出槽位的预测 |
| 当事人现实行为 | 具体场景和重复行为 |
| 平稳状态反馈 | 日常互动方式 |
| 压力状态反馈 | 分歧时第一反应 |
| 修复反馈 | 实际怎样重新靠近 |
| 匹配程度 | 完全／部分／不符／信息不足 |
| 可能原因 | 规则内容、权重、主次、去重或基础事实问题 |
| 涉及规则ID | 需保留、修改或停用的规则 |
| 验证结论 | 保留／降权／改写／停用 |

## 23.3 必须警惕的验证偏差

- 用户的自我描述与伴侣观察可能不同；
- 单次冲突不能代表长期惯性；
- 当前关系阶段不能代表所有关系；
- 文化、性别角色和家庭分工会影响表达方式；
- 工作压力、健康状态和现实资源会改变互动通道；
- 用户可能把“想怎样相处”说成“实际怎样相处”；
- 不能为了让案例吻合而事后无限增加解释。

建议至少同时收集：

1. 用户自述；
2. 一至两个具体事件；
3. 若可能，伴侣或长期亲近者的观察；
4. 不同关系阶段的差异。

# 24. 当前已经锁定的架构原则

1. M3 只描述关系建立后的互动惯性，不判断风险和适配；
2. 日支代表关系运行环境，不直接等于配偶人格；
3. M3 以日柱和五类功能系统为主，夫妻星只做接口和修正；
4. 十神决定互动通道，状态决定通道是否外显、稳定和顺畅；
5. 旺不等于好，弱不等于没有；
6. 喜忌修饰表达质量，不等于用户喜不喜欢这种方式；
7. 正偏十神必须拆开；
8. 平稳状态、压力状态和恢复状态必须分开；
9. 分歧响应不等于关系风险；
10. 需要空间不等于回避，直接表达不等于攻击，行动解决不等于冷漠；
11. 修复路径必须有真实回流证据，不能凭想象补足；
12. 同一个命理事实只能计算一次基础权重；
13. 每个最终字段有自己的主权威，不能用总分强行覆盖；
14. 最终正文必须控制输出数量；
15. 所有规则在案例校准前统一标记 `待验证` 和 `provisional=true`。
