# 八字关系分析系统 M0-M5 模块接口契约 V1.0

版本：V1.0  
适用Schema：`八字关系分析系统_M0-M5统一JSON_Schema_V1.0.json`

---

## 1. 契约目标

本契约解决四个开发问题：

1. 每个模块允许读取什么；
2. 每个模块负责计算什么；
3. 每个模块禁止覆盖什么；
4. 资料不足、冲突和安全停止时怎样返回。

## 2. 统一模块返回对象

每个模块统一返回：

```json
{
  "module_id": "M0.M09",
  "version": "1.9",
  "status": "complete",
  "outputs": {
    "day_master_strength": {
      "status": "supported",
      "value": "中和偏弱",
      "confidence": "medium_high",
      "evidence_level": 3,
      "rule_ids": [],
      "source_ids": [],
      "event_ids": [],
      "conditions": [],
      "counterevidence": [],
      "notes": ""
    }
  },
  "rule_ids": [],
  "dependency_flags": [],
  "warnings": [],
  "errors": []
}
```

`status`枚举：

```text
not_run
partial
complete
limited
stopped
dependency_pending
```

输出字段不得只返回一个字符串；至少要保留状态、值、置信度、规则ID和来源ID。

## 3. 统一输入对象

### 3.1 出生资料

```json
{
  "subject_id": "A",
  "birth_date": "1990-01-01",
  "birth_time": "12:30",
  "birth_time_status": "exact",
  "timezone": "Asia/Shanghai",
  "calendar": "gregorian",
  "birth_location": "optional",
  "gender_policy_value": "optional",
  "four_pillars": null,
  "data_quality": "high"
}
```

输入处理顺序：

```text
日期／时刻／时区
→
历法转换
→
节气交界
→
四柱
→
日主与月令
→
M0
```

出生时刻不确定时，必须显式标记`approximate`或`unknown`，并停止或降级受时柱影响的结论。

### 3.2 现实关系资料

```json
{
  "source_records": [],
  "event_records": [],
  "reality_gate_answers": [],
  "privacy_mode": "anonymous"
}
```

现实资料不允许由命盘补写。没有现实资料时，PARTNER、EXCHANGE、BOUND、REPAIR、RHYTHM和具体对象FG必须保持低等级或未评估。

## 6. 跨模型读取规则

### 6.1 M1

允许读取：

- M0日主、十神、夫妻星相关有效状态；
- M0根气、位置、喜忌和合化状态；
- 传统夫妻星策略配置。

禁止：

- 重新计算旺衰；
- 把心动写成关系结果；
- 由夫妻星推出职业、收入和社会地位。

### 6.2 M2

允许读取：

- M0夫妻星、夫妻宫、关系效应和功能状态；
- M1心动入口，作为差异背景。

禁止：

- 把确认快慢换算为具体天数；
- 把准入通过写成长期适配；
- 用年龄或社会压力替用户作选择。

### 6.3 M3

允许读取：

- M0关系底盘与十神功能；
- M2选择与确认结果。

禁止：

- 把命主个人惯性写成双方互动事实；
- 在没有对象资料时判断对方行为；
- 覆盖M0基础状态。

当前返回必须包含：

```text
dependency_flags:
- M3_REPAIR_PENDING
- M3_STATE_PENDING
- M3_SYNTH_PENDING
```

受上述依赖影响的M4／M5字段不得给最高置信。

### 6.4 M4

允许读取：

- M1高估信号；
- M2准入和确认路径；
- M3表达、付出、边界和冲突惯性；
- M0病药、流通与保护资源。

禁止：

- 把风险候选当作现实伤害；
- 把潜在保护当作已经有效；
- 把双方普通冲突框架用于现实强制与控制。

### 6.5 M5

允许读取：

- M0-M4全部已发布字段；
- 具体对象行为和双方现实事件；
- RG01—RG08现实资料。

必须分开：

```text
M1 attraction
M2 selection
M3 personal interaction
M4 risk
M5 fit
```

必须满足：

- 具体对象判断需要现实事件；
- FG3需要跨场景现实证据；
- FG4需要压力、修复或重大转折；
- RG01安全失败直接停止；
- 核心RG失败不能被结构高分覆盖。

## 7. 字段权威与冲突路由

统一裁决顺序：

```text
现实安全
→
出生输入完整性
→
M0基础事实
→
M0严格硬约束
→
M0根本主病／主路径
→
模块字段权威
→
现实核心RG
→
证据等级
→
累积分与风格候选
```

同一字段出现不同模块结论时：

1. 查字段权威；
2. 检查是否是不同阶段或不同对象；
3. 检查source_id／event_id重复；
4. 检查资料是否只是unknown；
5. 若主权威内部冲突，保留并列候选、条件和低置信，不取平均。

| 错误码 | 含义 | 处理 |
|---|---|---|
| `E_INPUT_MISSING` | 出生或现实关键资料缺失 | 字段unknown或模块limited |
| `E_CALENDAR_BOUNDARY` | 节气、时区或历法边界未核准 | 停止受影响M0链 |
| `E_M0_BASE_CONFLICT` | 旺衰、合化或基础映射争议 | 回退上位功能，降低置信 |
| `E_MODULE_DEPENDENCY` | 上游模块未完成 | dependency_pending |
| `E_M3_PENDING` | M3缺失模块影响下游 | 保留provisional |
| `E_REALITY_INSUFFICIENT` | 具体对象现实资料不足 | 最高FG2 |
| `E_CORE_GATE_UNKNOWN` | 核心RG未知 | 最高FG2 |
| `E_CORE_GATE_FAIL` | 核心现实方向不匹配 | AF08／最高FG2 |
| `E_SAFETY_STOP` | 暴力、强迫、控制或身体越界 | report_status=stop |
| `E_SCHEMA_INVALID` | 输出不符合统一Schema | 不发布 |
| `E_DUPLICATE_SOURCE` | 同一source_id重复计分 | 去重并重算 |
| `E_DUPLICATE_EVENT` | 同一event_id重复计数 | 合并事件 |
| `E_EVIDENCE_OVERREACH` | 结论超过证据层级 | 降级 |
| `E_DYNAMIC_MODEL_REQUIRED` | 用户要求具体时点或岁运事件 | 转D0 |

## 9. 推荐API

### 9.1 `POST /v1/m0/analyze`

输入：一份出生资料。  
输出：完整M0对象。

### 9.2 `POST /v1/relationship/profile`

输入：命主出生资料。  
输出：M1、M2、M3、M4结构候选和M5长期需要；不评价具体对象。

### 9.3 `POST /v1/relationship/evaluate`

输入：命主出生资料＋具体对象现实资料，可选对象出生资料。  
输出：M0-M5、RG、AF、FG、证据和报告。

### 9.4 `POST /v1/calibration/case`

输入：冻结预测、匿名事件和现实金标准。  
输出：字段核验、规则命中、反例和变更候选。

## 10. 编排伪代码

```python
def analyze_relationship(request):
    ctx = validate_request(request)

    m0 = run_m0(ctx.subject_a)
    if m0.status == "stopped":
        return build_limited_report(ctx, m0)

    m1 = run_m1(m0, ctx.policy)
    m2 = run_m2(m0, m1, ctx.policy)
    m3 = run_m3(m0, m2)
    m4 = run_m4(m0, m1, m2, m3)

    if ctx.analysis_mode == "single_chart_relationship_profile":
        m5 = run_m5_structure_only(m0, m1, m2, m3, m4)
    else:
        m5 = run_m5_with_reality(
            m0=m0,
            m1=m1,
            m2=m2,
            m3=m3,
            m4=m4,
            partner_events=ctx.event_records,
            reality_gates=ctx.reality_gate_answers,
        )

    result = resolve_global_conflicts(
        modules=[m0, m1, m2, m3, m4, m5],
        field_authority=FIELD_AUTHORITY,
        dedup=True,
    )

    validate_json(result)
    return build_report(result)
```

## 12. 发布前契约测试

- 45项M0字段全部存在或显式unknown；
- M1字段不足31时补空值，不改变语义；
- M3依赖标记不会丢失；
- M20／M21不被运行时执行；
- source_id与event_id去重；
- M2-TEMPO和M5-RHYTHM不混用；
- 安全停止覆盖所有普通适配；
- 只有命盘不进入FG3；
- 核心RG未知不进入FG3；
- 输出通过统一JSON Schema；
- 报告不出现唯一正缘、必然结婚、医学诊断或关系指令。
