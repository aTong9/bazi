# M5 关系适配真实案例校准方案 V0.10

## 1. 本阶段的定位

M5 V0.9已经完成七个前置模块、SYNTH总合成、3928条规则、RG现实门槛、FG证据等级、AF适配状态和统一JSON结构。

V0.10不继续增加关系理论，而是建立一套可以反复使用的真实案例校准流程，重点检验：

- 预测是否在查看反馈前被冻结；
- 规则是否把命盘结构越级写成现实结论；
- 心动、准入、对象能力、交换、边界、修复、节奏和现实门槛是否被正确区分；
- 同一source_id与event_id是否被重复计分；
- FG、AF和置信度是否超过现实证据；
- 安全、身体同意、关系意图、婚育家庭和人生目标是否被结构分数覆盖；
- 用户语言是否过度、笼统、不可证伪或带有决定论。

当前基线：

```text
baseline_model_version = 0.9
calibration_workbench_version = 0.10
baseline_rule_count = 3928
validation_status = 待验证
real_case_count = 0
```

## 2. 硬原则

1. **基线冻结**：V0.9源规则不原地修改，所有修订先进入候选变更。
2. **预测先冻结**：查看完整反馈前，先保存AF、FG、主需要、主差异、规则ID和观察计划。
3. **现实先标注**：金标准只看具体事件，不看预测代码。
4. **逐字段核验**：不用笼统“准／不准”，分别核验每个输出字段。
5. **未知不算错**：资料不足、场景未发生和字段不适用，标记“不可评估”。
6. **同源去重**：同一source_id和event_id只算一次基础证据。
7. **开发／留出分开**：开发集发现问题，留出集检验候选修改。
8. **反例优先**：强反例、安全漏判和现实门槛漏判优先于一般支持。
9. **安全独立统计**：安全漏判不能被高平均一致度抵消。
10. **变更可追溯**：每次修改必须有change_id、案例依据、开发结果、留出结果和回归测试。

## 3. 校准工作流

```text
冻结V0.9基线
        ↓
分配case_id与开发／留出集
        ↓
在查看完整反馈前冻结预测
        ↓
采集匿名关系事件
        ↓
独立标注RG与字段金标准
        ↓
逐字段比较预测与现实
        ↓
记录规则命中、反例和错误类型
        ↓
在开发集形成候选修改
        ↓
运行32项结构回归测试
        ↓
打开留出集检验
        ↓
决定保留、修改、拆分、合并、降权或停用
```

## 4. 建议校准周期

| 周期 | 建议规模 | 目的 | 发布边界 |
|---|---:|---|---|
| C0 结构回归 | 32项 | 检查安全、去重、RG、FG、AF与报告边界 | 全部通过 |
| C1 干跑 | 5例 | 熟悉冻结、采集、标注和日志 | 不用于阈值发布 |
| C2 首轮试点 | 20例 | 14开发＋6留出，发现越级和假阳性 | 不宣称准确率 |
| C3 扩展校准 | 40例 | 补足模块、阶段和反例覆盖 | 重点看留出集 |
| C4 稳定校准 | 80例 | 加入压力、修复、转折和核心RG | 阈值与语言趋稳 |
| C5 发布候选 | 120例以上 | 完整留出检验与版本审查 | 生成下一版候选 |

样本结构建议：

- 反例与混合案例合计不低于30%；
- 至少25%包含现实压力或代价；
- 至少20%包含分歧、修复或恢复过程；
- 至少15%包含异地、同居、婚育、家庭或职业转折；
- RG01、RG02、RG03、RG06、RG07、RG08优先完整评估；
- 不主动收集危险细节，安全事件只记录完成判断所需的最少事实。

## 5. 金标准与匹配评分

| 匹配等级 | 分值 | 含义 |
|---|---:|---|
| 完全支持 | 1.00 | 核心功能、状态和优先级一致 |
| 基本支持 | 0.75 | 核心方向正确，细节或强度略有差异 |
| 部分支持 | 0.50 | 只支持一部分，或仅在明确条件下成立 |
| 相邻但不同 | 0.25 | 同一功能族或相关任务，但主次／角色不对 |
| 反例 | 0.00 | 现实与预测核心方向相反 |
| 不可评估 | 不计 | 资料不足、场景未发生、字段不适用或不可证伪 |

金标准层级：

```text
G0 无资料
G1 单方抽象印象
G2 单方详细事件
G3 双方反馈或客观记录
G4 跨场景重复
G5 压力或现实代价
G6 修复与恢复
G7 反例和重大转折检验
```

第二轮复核由另一位复核者完成；只有一位分析者时，至少间隔7天盲重标。

## 6. 核心校准指标

工作台使用以下工程指标，不把它们表述成科学准确率：

```text
可评覆盖
=
可评字段数 ÷ 已预测字段数

加权一致度
=
(完全支持
＋0.75×基本支持
＋0.5×部分支持
＋0.25×相邻不同)
÷ 可评总数

反例率
=
反例数 ÷ 可评总数

证据越级
=
预测证据层 > 现实证据层

开发—留出差距
=
开发集一致度－留出集一致度
```

还必须单独记录：

- 安全漏判数；
- 核心RG漏判数；
- 反馈后新增规则数；
- 强反例数；
- 不可证伪语言数；
- 同源重复与event重复数。

## 7. 规则生命周期

| 样本阶段 | 可评数 | 允许结论 |
|---|---:|---|
| P0 待验证 | 0 | 不判断 |
| P1 极少样本 | 1—2 | 只记录 |
| P2 探索 | 3—5 | 可提出问题 |
| P3 初步 | 6—11 | 可形成修改候选 |
| P4 稳定候选 | 12以上 | 仍需留出集和反例审查 |

工作台的自动建议只用于筛查：

- 有安全漏判：立即安全审查；
- 可评不足3：样本不足；
- 反例率达到0.60且可评至少4：停用候选；
- 反例率达到0.40且可评至少6：优先修改；
- 可评至少8、加权一致度至少0.75、反例率不高于0.15且无强反例：保留观察；
- 开发和留出一致度差距超过0.25：疑似过拟合。

任何自动建议都不能直接修改V0.9。

## 8. 错误与反例分类

重点错误类型包括：

- 证据越级；
- 假阳性与假阴性；
- 功能族错类；
- 主次优先错误；
- 状态／阶段错判；
- 同源或event重复；
- 伪适配未排除；
- 现实门槛漏判；
- 安全门槛漏判；
- 语言过度与不可证伪；
- 缺失资料被误判；
- 历史对象与当前对象混淆；
- 字段权威冲突；
- 阈值失准与开发集过拟合。

## 9. 变更发布规则

一项修改进入下一版候选前必须同时具备：

1. 明确的rule_id、字段或阈值；
2. 旧内容与候选新内容；
3. 支持案例和反例案例；
4. 修改理由对应具体错误类型；
5. 开发集结果；
6. 32项结构回归测试全部通过；
7. 留出集结果；
8. 无新增安全漏判；
9. 生效版本与复核者；
10. 必要时保留旧规则并做情境拆分，而不是简单删除。
