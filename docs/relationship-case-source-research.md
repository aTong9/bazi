# 八字情感规则公开验证数据源研究

检索日期：2026-08-09

## 结论先行

目前没有发现一个同时满足以下条件的现成公开数据集/API：可核验到分钟的出生时间、出生地点、
结婚/分居/离婚等关系事件日期、允许批量获取，并可直接用于商业产品或 AI 训练。

可落地的方案是把用途分开：

1. **公开回放集**：只选公众人物或已故者，以 Astro-Databank 的高等级记录寻找出生时刻，
   再用民事登记、法院文书、本人声明等独立来源核验关系事件。它适合发现实现错误和做预注册的
   规则评估，但不能计入“匿名真人盲评”或“命理师审核签名”。
2. **统计对照集**：CDC NSFG 等官方调查可以检验婚姻事件的总体基线，却没有可排四柱的精确
   出生时分与地点，不能逐人验证八字。
3. **受许可的队列验证集**：UCL BCS70 是目前找到的最佳大样本候选：出生调查记录出生小时，
   后续纵向数据记录伴侣关系史。但它只到小时、地点字段须按实际数据包确认，并受 UK Data Service
   访问与禁止再分发约束，不能直接内置产品。
4. **产品验证集**：最现实且权利最清楚的来源仍是自愿参与者。单独取得出生资料、关系事件、
   研究验证和产品改进的明示授权，去标识后由独立审核者盲评。

公开案例只能补充证据，无法绕过 roadmap 中的真人审核门槛。

## 推荐的公开情感案例准入门槛

公开人物只能进入独立的 `PUBLIC_EVENT_REPLAY` 集，并同时满足：

1. 出生时刻达到项目的 `BIRTH_AA_VERIFIED` 或 `BIRTH_AA_REPORTED`；日期、时分、地点和来源分别保存，
   不因 ADB 标注 `AA` 就声称项目看过原件。
2. 每个关系事件至少有一条**独立于出生来源**的一手记录；次选双方本人可定位声明或同期权威报道。
   ADB、Wikidata和媒体如果都转引同一公告，只算一条证据链。
3. 明确区分 `dating_start`、`cohabitation_start`、`legal_marriage`、`separation`、`divorce_filing`、
   `divorce_effective`、`partner_death`。不把媒体首次报道日自动当成事件发生日。
4. 保存 `date_precision`（日/月/年/区间）和冲突候选；只有日级事件可进日级测试，年级事件不能伪造为
   1 月 1 日。出生时刻疑似整点取整或靠近时辰/日界者进入单独边界组。
5. 预先冻结人物、规则和允许的命中窗口，再看结果；保留未命中案例，禁止按“应验”反向挑人。
6. 只选公众人物或已故者，不收集证件号、住址、子女隐私、性取向等与测试无关的字段。

建议首批只建立 20 个高证据案例，不追求数量。每个案例至少一段可检验的婚姻/关系区间，另设
年龄、性别、既往婚史等朴素基线。这个集合能做软件回放与探索性准确率，不能宣称因果或预测有效。

## 人类审核有没有合法替代方案

没有能把“公开资料”自动变成项目审核签名的合法替代方案：

- **同行评议论文**可以成为规则的外部证据或反证，但审稿人没有逐条审过本项目的规则版本、措辞、
  实现和证据 ID，不能写成 `reviewer_signed=true`。
- **古籍原文**只能证明规则出处；版本、断句、现代化翻译、适用条件和冲突裁决仍需项目审核。
- **问真/其他产品输出一致**只证明兼容性，不证明规则正确，也不是独立人工审核。
- **AI 审核**可发现格式和证据引用错误，但不能成为责任主体或替代命理师/领域专家签名。

可行的降成本方案不是取消审核，而是把审核做得可审计：

1. 聘请至少两名相互独立的领域审核者，签署数据处理和利益冲突声明；界面隐藏规则作者与案例结果。
2. 每条规则分别判断“出处准确、实现忠实、适用条件完整、文案不过度断言”，保留规则版本、reviewer ID、
   时间戳和理由；分歧交由第三人裁决。
3. 对真人案例，审核者只看去标识的结构化命盘与预注册标签，不看姓名和用于选择案例的来源。
4. 在分析前用 [OSF 预注册](https://help.osf.io/article/330-welcome-to-registrations)冻结假设、样本准入、
   命中窗口、排除条件和指标。OSF 将预注册定义为采集/分析前发布的带时间戳只读研究计划；它能减少
   事后改规则，但仍不替代审核者。
5. 最终报告同时列出命中、未命中、无法判断、审核者一致率及朴素基线；公开研究集与产品匿名集分开统计。

## 建议执行顺序

1. 先建立 `PUBLIC_EVENT_REPLAY` 的空 schema 和证据等级，不接任何自动爬虫。
2. 人工挑选 20 个 ADB 高等级公众人物候选；在未获许可前只保存最小事实、来源指针和本项目计算结果，
   不复制 ADB 传记、source notes 全文或整库分类。
3. 对每个婚姻事件回到登记机关、法院、本人公告或同期记录；不够日级精度就明确降级。
4. 用 Wikidata QID 去重和找 reference；批量阶段遵守官方访问规范，绝不从 Wikidata推断出生时分。
5. 向 UK Data Service 申请 BCS70 birth sweep 与 partnership histories 联合研究，先确认出生小时、
   可用出生地精度、链接键、商业项目分类和允许输出；只输出汇总指标，不把微观数据复制进仓库或产品。
6. 并行启动自愿参与者招募与双人盲评。只有这条线能补齐匿名真人数量和审核签名；公开名人集继续作为
   回归/探索证据，不混入产品有效性数字。

以上是工程和研究数据治理建议，不是针对具体司法辖区的法律意见；商业上线前仍应由适用辖区的专业人员
审核同意文本、隐私政策和第三方数据许可。
