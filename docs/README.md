# 十、整合中发现的开发优先项

## 第一优先：补齐M3

当前M3只有：

```text
M3-BASE
M3-EXPR
M3-CARE
M3-BOUND
M3-CONFLICT
```

仍缺少：

```text
M3-REPAIR
M3-STATE
M3-SYNTH
```

这些缺口会影响：

* M4修复接口；
* M5修复协议；
* M5压力与恢复节奏；
* M3自身统一报告；
* 最终置信度。

在补齐以前，相关输出已经统一要求：

```text
status = dependency_pending
confidence 降级
dependency_flags 明确记录
```

## 第二优先：完成M0代码实现

应严格按照：

```text
M02基础映射
→
M03月令根气
→
M04/M05关系识别
→
M06逐对象效应
→
M07原始旺衰
→
M08有效旺衰
→
M09日主旺衰
→
M10十神功能
→
M11十神组合
→
M12流通
→
M13调候
→
M14格局候选
→
M15格局成败
→
M16病药
→
M17喜忌用神
→
M18冲突裁决
→
M19统一输出
```

## 第三优先：再接M1—M5

不能绕过M0直接从原始四柱运行M1—M5，否则会再次出现：

* 旺衰重复计算；
* 合化状态不一致；
* 喜忌结果冲突；
* 同一事实重复加分；
* 模型之间相互覆盖。

## 第四优先：D0单独建设

当前系统M0—M5都是原局结构与关系模型，不负责：

* 大运；
* 流年；
* 具体相遇年份；
* 婚期；
* 分手或复合日期；
* 事件月份。

这些内容已经统一转交尚未建设的：

```text
D0 动态岁运与事件时点模型
```

目前最合理的开发起点是：先建立项目代码骨架、统一数据对象和Schema校验，再按M02—M06实现M0第一条可运行链。
