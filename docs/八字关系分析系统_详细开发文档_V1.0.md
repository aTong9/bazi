# 八字关系分析系统 M0—M5 详细开发文档 V1.0

状态：开发基线
适用整合版本：Integration V1.0
编制日期：2026-08-29
实施技术栈：TypeScript、Node.js 22、Ajv Draft 2020-12、SQLite
适用范围：M0—M5 静态分析系统；D0 动态岁运与具体时点不在本期范围

## 1. 文档目的

本文档把整合包中的规则、接口、迁移、测试和校准资料转换成可直接实施的工程方案。

后续开发者和开发代理应先阅读本文，再按具体任务读取被引用的权威文件。本文负责：

- 冻结当前工程架构和依赖方向；
- 明确权威源、生成物和运行时数据的边界；
- 定义领域对象、状态、证据、置信度和发布门控；
- 规定数据编译、Schema、API、持久化和测试策略；
- 给出分阶段产物、退出条件、风险和 Definition of Done；
- 防止把自然语言规则、未验证规则或历史测试结果误当成生产能力。

本文不复制全部规则正文。规则含义仍以原始权威文件为准；本文只规定它们如何被治理、编译、执行和验收。

规范用语：

- “必须”表示合并或发布的硬性门槛；
- “应”表示默认方案，改变时需要 ADR；
- “可以”表示不影响核心契约的实现选择；
- “不得”表示安全、字段权威或数据完整性禁区。

### 2.2 三类权威

系统不存在一个覆盖所有问题的单一最高文件。必须按职责选择权威。

| 关注点 | 权威源 | 使用方式 |
|---|---|---|
| M0 规则原意和专用字段 | M0 V1.9 核心工作簿 | 语义编写真源，只读 |
| M1—M5 规则原意 | 各模块最新原子规则 CSV | 语义编写真源，只读 |
| 当前整合版本、数量和核心入口 | 系统版本清单及 02_运行时核心 | 集成契约 |
| 字段所有权 | 字段权威矩阵 | 下游只读，不得重算 |
| 外层 API 对象 | 统一 JSON Schema | 裁决冲突后生成新版端点契约 |
| M4/M5 模块内部对象 | 各自模块 Schema | 通过显式 Adapter 转换 |
| 迁移和冲突 | 冲突裁决清单、M21 | 构建治理依据 |
| 测试案例 | M20、开发测试矩阵 | 测试资产，不进普通运行时 |
| 历史文件 | 06_历史归档 | 只用于审计 |

需要区分：

- **语义编写真源**决定一条规则原本表达什么；
- **集成契约**决定 Integration V1.0 包含哪些记录、字段和版本；
- **编译生成物**决定某个应用版本实际能执行哪些规则；
- **用户现实资料**决定具体关系证据和安全事实。

任何两层不一致时，构建必须停止并产生 ImportConflict；不得静默回退到另一个文件。

## 4. 产品范围与硬边界

### 4.1 三种主要运行模式

| 模式 | 输入 | 可以输出 | 发布上限 |
|---|---|---|---|
| single_chart_structure | 一份出生资料 | 完整 M0 原局结构 | 不评价具体对象 |
| single_chart_relationship_profile | 一份出生资料 | M1—M4 结构候选、M5 长期需要和观察标准 | 不得进入 FG3/FG4 |
| specific_partner_with_reality_data | 命主资料、现实行为、事件和 RG，可选对象命盘 | 具体对象、交换、边界、修复、节奏、RG、AF、FG | 由现实证据和安全门决定 |

two_chart_supplementary 只能增加双方结构背景，不能替代行为、同意、边界、交换、修复和现实目标。

### 4.2 禁止输出

M0—M5 不得直接输出：

- 唯一正缘；
- 必然结婚、必然长久或必然分手；
- 具体婚期、相遇月份、分手日期或大运流年事件；
- 伴侣职业、收入、外貌、生肖或道德定性；
- 医学诊断和用药建议；
- 因适配等级而要求用户进入、继续、原谅或复合；
- 把 FG 表述为成功概率；
- 把 AF 表述为命定结局。

具体时点请求必须返回 E_DYNAMIC_MODEL_REQUIRED。出生日期到四柱的历法和节气换算属于输入标准化，不属于 D0。

### 4.3 安全硬门

以下现实事件具有否决权：

- 暴力或威胁；
- 强迫、跟踪、监控；
- 经济控制；
- 身体或性边界侵犯；
- 撤回同意后仍继续；
- 基本选择权、退出权或退出资源被剥夺。

命中安全停止时必须同时满足：

~~~text
safety_status = safety_stop
report_status = stop
fit_grade = FG0
final_fit_state = AF09
~~~

普通互补、修复、适配及“保护因素抵消风险”的叙事必须停止。安全规则不能进入平均分或加权抵消。

## 5. 架构决策

### 5.1 模块化单体

采用 TypeScript、Node.js 22 的模块化单体仓库，不把 M0—M5 拆成微服务。

原因：

- M0—M5 有紧密且固定的依赖 DAG；
- 一次分析必须固定同一个规则快照；
- 字段权威、去重、全局裁决和安全停止必须原子完成；
- 当前主要复杂度是规则编译和校准，而不是独立扩容；
- 清晰的端口和 Adapter 仍保留未来拆分能力。

领域层不得依赖 HTTP、SQLite、CSV、Excel 或具体历法库。

### 5.2 确定性规则引擎

同一输入、同一规则快照和同一策略配置必须产生相同领域结果。

生产运行时只执行经过人工复核和测试的类型化 Rule IR。自然语言字段保留为审计资料，但不得在请求期间交给 LLM 或通用文本解释器判断是否命中。

系统可以使用 AI 辅助开发、整理候选映射或生成审阅建议；AI 输出进入生产规则前必须转换为显式 IR、通过人工复核和回归测试。

### 5.3 双重校验

JSON Schema 负责结构合法性，SemanticValidator 负责跨字段业务不变量。

两者任一失败都不得发布结果。系统错误不能包装成正常的 unknown。

### 5.4 SQLite 双数据域

首版采用两个 SQLite 数据域：

~~~text
catalog.sqlite
  规则、版本、模块、字段字典、编译 IR、快照清单
  发布后只读

app.sqlite
  请求、事件、模块运行、字段结果、决策日志、报告
  运行时读写
~~~

校准规模扩大后再增加 calibration.sqlite。用户案例不得直接写回规则库。

## 7. 有界上下文与职责

### 7.1 Catalog 与治理

负责源文件导入、哈希、ID、列、数量、版本、依赖、迁移映射、IR 编译、快照发布及规则弃用。它不执行用户分析。

### 7.2 出生输入与历法

负责日期、时间、时区、地点、历法、节气交界、四柱生成或校验，以及输入质量和受影响字段。

历法实现必须位于 CalendarPort 后面。具体库、节气数据源、真太阳时策略和边界窗口通过 ADR 冻结。

### 7.3 M0 原局

M0 拥有所有原局静态事实：

~~~text
M02—M05 识别
→ M06 逐对象效应
→ M07—M13 结构
→ M14—M17 候选与功能
→ M18 全局冲突裁决
→ M19 45 项输出
~~~

硬性不变量：

- 关系识别不等于实际效应；
- 原始力量不等于有效力量；
- 十神旺衰不等于喜忌；
- 格局候选不等于格局成立；
- M17 不得绕过 M18；
- M19 的 45 个字段必须全部出现；
- M20、M21 不进入普通推理。

### 7.4 关系画像 M1—M4

- M1：心动和吸引入口；
- M2：关系准入、选择及进入关系前的确认节奏；
- M3：进入关系后的个人表达、照顾、边界和冲突惯性；
- M4：误读、过用、触发、循环、修复卡点和保护候选。

M3 个人惯性不是双方现实事实；M4 结构风险不是已发生伤害。

在 M3.REPAIR、M3.STATE、M3.SYNTH 完成前，受影响结果必须 dependency_pending，并记录三个明确依赖标记。

### 7.5 M5 现实适配

~~~text
BASE
→ PARTNER
→ EXCHANGE
→ BOUND
→ REPAIR
→ RHYTHM
→ GAP
→ SYNTH
~~~

PARTNER、EXCHANGE、BOUND、REPAIR 和 RHYTHM 是不同的现实证据对象，不能压成一个总分。

### 7.6 报告

ReportBuilder 是投影器，不是推理模块。它只能选择已发布字段、组织章节、转换语言、添加观察计划和边界说明。

它不得：

- 补写不存在的事实；
- 重新评分；
- 提高字段状态、置信度或 FG；
- 根据文风生成新结论。

### 7.7 校准

校准案例先冻结预测和版本，再录入匿名现实金标准。校准只能产生 keep、modify_candidate、deprecate_candidate 或 needs_more_evidence。

规则变更必须经过人工审核、回归测试和新 Catalog Snapshot 发布。

## 8. Canonical Domain Model

### 8.1 聚合根

| 聚合根 | 作用 | 核心不变量 |
|---|---|---|
| AnalysisRun | 一次完整分析 | 全部模块固定同一快照 |
| RuleCatalogSnapshot | 可发布规则快照 | 不可变、可复现、依赖闭合 |
| CalibrationCase | 一次匿名校准 | 先冻结预测，后记录现实 |
| ReportPublication | 一次正式发布 | 结构和语义校验均通过 |

### 8.2 核心实体和值对象

| 类型 | 名称 | 说明 |
|---|---|---|
| 实体 | BirthSubject | 一位出生资料主体 |
| 值对象 | BirthInput | 日期、时刻、时区、历法、地点、质量 |
| 值对象 | NatalChartSnapshot | 不可变四柱和计算来源 |
| 实体 | RuleDefinition | 稳定 ruleId 对应的规则 |
| 实体 | ModuleRun | 一次分析中的模块执行 |
| 实体 | SourceRecord | 一项可追溯来源 |
| 实体 | EventRecord | 一个现实事件，同一 eventId 只计一次 |
| 实体 | RealityGateAssessment | RG01—RG08 的单门判断 |
| 实体 | DecisionRecord | 接受、拒绝和冲突裁决 |
| 值对象 | ResultItem<T> | 值、状态、置信、证据和追踪 |
| 值对象 | EvidenceDepth | 证据体系及该体系内深度 |
| 值对象 | SafetyDecision | 安全状态和停止理由 |
| 值对象 | FitPublication | FG、AF 及门控理由 |
| 值对象 | VersionManifest | 本次运行的完整版本集 |
| 投影 | AnalysisReport | 用户可见报告 |

### 8.3 核心类型

~~~ts
export type ResultStatus =
  | "not_assessed"
  | "unknown"
  | "candidate"
  | "supported"
  | "conditional"
  | "contradicted"
  | "stopped";

export type ApplicabilityStatus = "applicable" | "not_applicable";

export type ModuleStatus =
  | "not_run"
  | "partial"
  | "complete"
  | "limited"
  | "stopped"
  | "dependency_pending";

export type ConfidenceLevel =
  | "high"
  | "medium_high"
  | "medium"
  | "medium_low"
  | "low"
  | "not_applicable"
  | "unknown";

export type EvidenceScheme = "PV" | "XV" | "BV" | "FV" | "HV" | "GE";
export type EvidenceLevel = 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7;

export interface EvidenceDepth {
  scheme: EvidenceScheme;
  level: EvidenceLevel;
}

export interface ResultItem<T> {
  applicability: ApplicabilityStatus;
  status: ResultStatus;
  value: T | null;
  confidence: ConfidenceLevel;
  evidence: EvidenceDepth | null;
  ruleIds: readonly string[];
  sourceIds: readonly string[];
  eventIds: readonly string[];
  conditions: readonly string[];
  counterevidence: readonly string[];
  notes?: string;
}

export interface ModuleRun<TOutputs> {
  moduleId: string;
  moduleVersion: string;
  status: ModuleStatus;
  outputs: TOutputs;
  matchedRuleIds: readonly string[];
  dependencyFlags: readonly string[];
  issues: readonly DomainIssue[];
}
~~~

内部领域类型应比外部 JSON 更严格。外层 Schema 通过 Adapter 接收投影，不能为了兼容旧 Schema 而削弱内部类型。

## 9. 状态和证据必须分离

| 维度 | 回答的问题 | 字段 |
|---|---|---|
| 运行资格 | 源记录是否允许进入普通运行时 | runtimeEligible |
| 编译状态 | 是否已成为可执行 IR | compilationStatus |
| 规则生命周期 | 当前规则是否可采用 | lifecycleStatus |
| 模块状态 | 本次模块是否完整运行 | ModuleStatus |
| 适用状态 | 当前字段是否适用于本次模式 | ApplicabilityStatus |
| 字段状态 | 当前字段结论的性质 | ResultStatus |
| 字段置信 | 结论可靠程度 | ConfidenceLevel |
| 证据深度 | 哪类证据达到多深 | EvidenceDepth |
| 现实门 | 某一 RG 是否通过 | RealityGateStatus |
| 安全状态 | 是否允许继续普通分析 | SafetyStatus |
| FG | 证据允许的发布上限 | FitGrade |
| AF | 关系当前适配状态 | FinalFitState |
| 报告状态 | 报告能否发布 | ReportStatus |

语义约束：

- unknown 是未知，不是负面证据；
- not_assessed 是未评估，不是评估失败；
- not_applicable 属于内部 ApplicabilityStatus，不是模块错误；
- 在 V1.0 外层响应中，不适用字段投影为 status=not_assessed、confidence=not_applicable，并在 conditions 中记录 NOT_APPLICABLE；
- 只有发布新 Schema ID 和迁移表后，才可以把 not_applicable 加入外层 ResultStatus；
- candidate 是结构候选，不是现实发生；
- confidence 不是统计概率；
- base_confidence 是规则元数据，不等于输出置信度；
- FG 是发布上限，不是成功率；
- AF 是当前状态，不是命定结局；
- “规则待验证”和“字段低置信”是不同概念；
- PV、XV、BV、FV、HV、GE 虽都可使用 0—7 深度，但不得互相求和或替换。

同一 sourceId 的基础权重只计一次；同一 eventId 只计一次事件，但可以支持多个字段。

## 10. 出生输入设计

### 10.1 判别联合

~~~ts
type BirthInput =
  | {
      inputMode: "four_pillars_provided";
      subjectId: string;
      fourPillars: {
        year: Pillar;
        month: Pillar;
        day: Pillar;

interface Pillar {
  stem: HeavenlyStem;
  branch: EarthlyBranch;
}
~~~

必须校验：

- 天干属于十干、地支属于十二支；
- 每柱属于合法六十甲子；
- 生产分析必须校验年干与月干符合五虎遁、日干与时干符合五鼠遁；
- 日柱必须存在；
- exact 模式必须有精确时刻或时柱；
- unknown 时辰允许 hour=null，但所有时柱依赖字段必须降级；
- civil_datetime 必须使用有效 IANA 时区；
- 传统夫妻星策略是显式配置，不与用户现实性别强绑定。

### 10.2 第一阶段输入边界

第一阶段只实现 four_pillars_provided。civil_datetime 在 Calendar Adapter 完成前返回明确的未支持错误，不能采用近似算法。

直接提供四柱只表示系统验证干支结构；它不表示系统已经复核出生日期、时区和交节。

analysis_mode=test 可以通过 synthetic_fixture=true 使用专门的合成组合测试识别器，但该输入必须标记为测试资料，不得保存为普通用户分析或生成正式报告。其他模式不得绕过五虎遁和五鼠遁一致性。

### 13.2 当前契约冲突的实施裁决

- 报告中的安全停止保留必要说明，但不暴露无关敏感细节；
- 运行时不执行来自 CSV、用户输入或数据库的代码；
- IR AST 不允许任意脚本、SQL 和网络调用；
- 规则快照使用内容哈希和只读打开方式。

## 20. CI 门禁

| Job | 触发 | 阻塞条件 |
|---|---|---|
| repo-contract | 每个 PR | 文档载荷、哈希、Schema、CSV、ID、数量、归档隔离失败 |
| static-quality | 每个 PR | 格式、lint、类型、lockfile 漂移失败 |
| p0-contract-safety | 每个 PR | 适用 P0、安全、字段权威或迁移失败；P0 skip 也失败 |
| impacted-modules | 每个 PR | 受影响模块单元、接口和回归失败 |
| full-matrix | 主分支、夜间、里程碑 | 当前阶段要求的测试失败 |
| performance | 夜间、发布候选 | 数值门槛或批准基线回退失败 |
| calibration-evidence | 发布候选、人工批准 | 样本、冻结、留出、安全或复核不足 |
| deploy | 标签或人工批准 | 任一发布门未通过 |

PR 验证和部署必须拆分。普通 master push 不应在未通过质量门时直接部署。

性能测试 PF004、PF005、PF010 目前没有可执行数值门槛；在 ADR-PERF-001 批准前不能作为发布证明。

满足样本和留出门槛前，产品不得使用“准确率”“成功率”或“已统计验证”措辞。

## 25. Definition of Done

### 25.1 单个任务

- 需求、字段权威、规则 ID 和测试 ID 可追溯；
- 正向、边界、否决、unknown、停止和依赖缺失路径有测试；
- 不修改只读真源；
- 派生数据由脚本生成；
- 结果包含规则、来源、事件和版本追踪；
- lint、类型、单元、契约和适用 P0 测试通过；
- 没有未登记的 skip、默认值或枚举扩展；
- 文档、Schema、迁移和实现同步。

### 25.2 单个模块

- 输入、输出、字段权威和停止条件已实现；
- 相关 P0/P1、接口、安全和回归通过；
- 规则数、ID、依赖和字段与权威源一致；
- provisional、unknown 和 dependency_pending 均有理由；
- 可以从固定提交、快照和 fixture 重现结果。

### 25.3 发布候选

- 407 项形成当前版本执行记录；
- P0/P1 失败、阻塞和安全漏判为 0；
- 150 项 M20 已按 V1.9 复测；
- 32 项 M5 结构回归通过；
- 性能门槛通过；
- M4/M5 达到批准的样本和留出门槛；
- 发布包、规则、Schema、迁移和测试哈希可复现；
- 统计门槛满足前继续禁止准确率和成功率声明。
