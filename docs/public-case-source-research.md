# 公开真人案例证据源研究

检索日期：2026-08-09

## 结论

适合本项目的公开案例不能从一个网站一次性取得。推荐把证据拆成两条互不替代的链：

1. **出生链**：以出生证、出生登记或其可核验影像为最高等级；Astro-Databank 的
   Rodden `AA` 记录可作为发现入口和索引，但导入时仍须保存其原始来源说明。
2. **事件链**：从奖项机构、体育组织、政府档案、法院/登记机关、本人声明或同期
   权威报道逐项取得。问真、Astro-Databank 或其他命理/占星站的生平文字不能充当
   独立事件证据。

因此，最稳妥的首批数据集不是“尽量多的名人”，而是 20–30 名有 `AA` 出生时刻、
出生地点明确、且至少有三项带日期的官方事件记录的现代公众人物。它适合做排盘回放、
时间边界测试和预先注册的规则评估；它仍不能替代匿名真人盲评。

### 对 Astro-Databank / Rodden Rating 的判断

Astro-Databank 是当前最实用的“有来源评级的出生时刻索引”，尤其适合从 `AA` 中建立
候选集。Rodden 等级评价的是**来源链类型**，不是分钟误差的统计保证：证件也可能晚填、
四舍五入或抄录错误，历史时区和夏令时还需本项目独立计算。故数据模型应同时保存：

- `reported_local_datetime`、地点原文、原始时区说明；
- `rodden_rating`、source notes 的具体文献/档案指针、是否亲眼核对原件；
- 时间精度（秒/分/5 分钟/15 分钟/小时/区间）和是否疑似整点取整；
- 本项目解析得到的 IANA 时区、UTC、真太阳时以及所用 tzdb/历法版本；
- 相互冲突的所有候选时间，不能只留下项目偏好的那个。

商业网站上线前必须单独解决 ADB 授权：其公开版权说明仅明确授予**非商业**复用，且明确
禁止 spidering。官方 2026 年[导出 README](https://www.astro.com/adbexport/00_readme.htm)
还说明完整导出暂停、不向非研究者授权，并明确拒绝以训练 AI 系统为目的的许可。当前可做人工、
小样本、可追溯研究；不能据此实现生产环境批量采集器，也不能把 ADB 数据用作文章模型训练集。
README 提到的 C 姓氏研究样本也应按研究用途和最新条款使用，不能因文件可下载就直接内置产品。

## 人生事件的权威来源方案

事件应存为独立记录，每项包含 `event_type`、开始/结束日期、日期精度、地点、source URL、
发布者、访问日期和证据等级。不要从一篇人物简介拆出十个事件后误算成十条独立来源。

| 事件类型与来源 | 能验证的事件 | 约束及用法 |
| --- | --- | --- |
| [Nobel Prize API 2.1](https://www.nobelprize.org/about/developer-zone-2/)及其[使用条款](https://www.nobelprize.org/about/terms-of-use-for-api-nobelprize-org-and-data-nobelprize-org/) | 获奖年份、类别、授奖份额、机构及官方人物资料 | 官方 REST API，无需 key，JSON/CSV，数据随官网更新；服务数据采用 CC0。适合作为“获重大专业奖项”的一手事件，不要把颁奖年份解释成更广泛的“事业必然成功” |
| [奥林匹克官方资料库/官方成绩册](https://library.olympics.com/) | 参赛、比赛日期、名次、奖牌、代表队 | 官方成绩册适合精确到比赛日；运动员简介中的生日通常没有出生时刻，只用于身份核对。保存赛事、项目和官方文档页码 |
| [Academy Awards 官方数据库](https://awardsdatabase.oscars.org/) | 奥斯卡提名、获奖、届次和类别 | 官方数据库是过往获奖和提名记录；页面未承诺通用批量 API，按站点条款人工或低频核验，不抓取人物传记文本 |
| [美国国会 Biographical Directory](https://history.house.gov/About/Biographical-Directory/) / [Congress.gov](https://www.congress.gov/members) | 任期开始结束、选区、职务、出生死亡日期、资料馆藏线索 | 由众议院书记官办公室和参议院历史办公室维护，线上条目日常更新。适合政治任职事件和继续追查官方档案，但通常无出生时刻 |
| 政府任免公报、选举委员会、法院判决/案卷、公司监管披露 | 就任、离任、当选、判决、破产、上市、高管任免 | 事件强度高且日期清楚；不同司法区的复用和隐私规则不同。法院案件应记录裁判日期与事件实际发生日期，二者不可混用 |
| 本人官网、所属机构公告、出版社、大学、协会或奖项官网 | 入职、毕业、作品发布、任命、获奖 | 属于事件当事方或主管机构的一手发布；适合职业事件。营销性质资料仍需避免把评价词当事实标签 |
| 民事婚姻/离婚登记、法院文件；其次是双方本人公告 | 结婚、离婚、分居 | 只有公开、合法可访问且涉及公众人物时使用；不尝试绕过封存或资格限制。娱乐媒体报道可作线索，不应单独成为最高等级证据 |
| 同期主流通讯社、报纸档案、权威讣告 | 事故、疾病公开披露、死亡、婚姻及职业节点 | 属于高质量二手来源。优先同期报道并要求可识别作者、日期和原始出版物；多个转载同一通讯社稿只算一个来源 |
| Wikidata/Wikipedia | 跨库实体 ID、候选事件和原始引用入口 | 只作发现层；最终 evidence URL 应指向它引用的官方档案或原始报道，而不是百科条目本身 |

医疗、性取向、犯罪受害、子女及其他敏感事件即使对公众人物公开，也不应为扩大样本量而
默认采集。若确与预先注册的测试问题相关，须采用最小字段、明确公共利益与来源，并经人工
审核；在世非公众人物一律不进入公开案例库。

## 建议的统一置信度分级

出生时刻和事件必须分别评级，不能以“这个名人很有名”替代证据质量：

- `BIRTH_AA_VERIFIED`：项目人员看过官方/家庭记录影像或档案馆签章摘录，能记录馆藏号。
- `BIRTH_AA_REPORTED`：ADB `AA` 且来源说明具体，但项目未查看原件。
- `BIRTH_A_DIRECT`：本人或近亲可定位的直接声明。
- `BIRTH_B_BIOGRAPHY`：具作者、书名、版本和页码的传记资料。
- `BIRTH_UNUSABLE`：`C/DD/X/XX`、校正时刻、没有原始来源、只有命理网站转述或日期冲突未解。
- `EVENT_PRIMARY`：主管机构、登记机关、法院、本人或事件承办方的一手记录。
- `EVENT_AUTHORITATIVE_SECONDARY`：可追溯的同期主流报道或严谨传记。
- `EVENT_DISCOVERY_ONLY`：百科、聚合站、粉丝站、命理/占星网站，不能单独进入评分。

一个案例的总体等级取出生链和所用事件链中的最低等级。缺时柱或时间是区间的案例仍可测试
年/月/日柱，但不得进入“四柱精确匹配”或时辰相关规则评估。

## 推荐首批案例准入标准

首批固定回放集建议按以下硬门槛筛选：

1. 公众人物，优先已故或明确公开其出生信息者；不收集私人联系方式、证件号码和亲属隐私。
2. 1900 年后出生，以降低地方平太阳时、历法变更和历史时区不确定性；出生地点能定位到市县。
3. `BIRTH_AA_VERIFIED` 或 `BIRTH_AA_REPORTED`；记录到分钟，并保留原始钟表时间。整点记录标记
   `possible_rounding=true`，节气/日界/时辰边界 ±30 分钟者单列，不混入普通样本准确率。
4. 至少三类可核验事件，每项至少达到 `EVENT_AUTHORITATIVE_SECONDARY`，其中至少两项为
   `EVENT_PRIMARY`；例如官方任职、比赛/奖项、作品发布，而不是三篇转载同一生平的文章。
5. 覆盖不同性别、地区、时区、夏令时与职业；不以事件结果筛选案例，避免只选“特别应验”的人。
6. 先冻结案例和判断规则，再计算结果；失败案例同样保留，版本升级只追加勘误记录。

建议首批 20–30 人，随后扩到 100 人。这个规模足以暴露时区、日界和节气边界问题，但不应
宣称能够证明命理预测有效；断语有效性需要预注册、盲评、对照基线及未参与规则编写的样本。

## 与问真名人库的去重和交叉验证

问真数据只应作为 `WENZHEN_REPLAY` 层。推荐流程：

1. 用 Wikidata QID（若有）作为跨库主 ID，辅以规范化姓名、别名、真实历史出生日期和地点；
   不用问真内部平移后的年份作身份键。
2. 对古代年份循环平移、`**` 时柱、日期缺失或人物重名分别标记，不自动合并。
3. 问真与 ADB 相同不算“两源一致”。只有 ADB source notes 指向的出生记录/传记与问真形成
   可解释的独立链时，才可称交叉核验；若两个站都引自同一资料，只算一个来源。
4. 保存字段级 provenance，例如“时刻来自出生证、地点来自官方传记、事件来自 Nobel API”；
   禁止只给整条人物记录一个笼统 `verified=true`。
5. 若独立资料与问真冲突，保留双方原始值和来源，建立 `conflict_status` 与人工裁决记录；固定测试
   默认采用证据等级更高者，同时继续用问真值测试“站点兼容性”。
6. 公共事件集与匿名真人盲评集使用不同统计报表。名人数据不可满足“匿名真人数量”或“命理师
   签署”门槛。

## 实施建议

近期可安全推进的顺序是：人工挑选 ADB `AA` 候选并申请/确认复用许可；对候选逐条回溯 source
notes；用 Wikidata QID 做实体对齐；从 Nobel、奥运、政府和奖项官网获取结构化事件；最后由两名
审核者独立确认来源和日期。仓库只保存事实字段、短来源摘录、哈希和链接，受限证件影像放在访问
控制的证据库而不是 Git。

在未取得 ADB 批量/商业授权前，不应开发爬虫，也不应把其页面文本、source notes 全文或分类体系
复制进产品。若授权不可得，可改走“自愿参与者授权上传出生证明 + 去标识事件问卷”的原创数据集，
这也是后续匿名真人盲评更可持续的来源。
